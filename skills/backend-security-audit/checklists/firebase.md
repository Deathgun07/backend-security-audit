# Firebase checklist

Sources: `firestore.rules`, `storage.rules`, `database.rules.json` (Realtime Database), `firebase.json`, `functions/` (Cloud Functions), client code (`initializeApp`), service account files.
Reminder: the web config (`apiKey: "AIza…"`, `projectId`) is **public by design** (Info). The only client-side barrier is the **Security Rules**. A rule in the repo that is not deployed may differ from prod: also check `firebase deploy --only firestore:rules` or the console (→ "to verify manually").

## FB1. Open rules (`if true`, no condition) — Critical (A01)
```js
// ❌ firestore.rules
match /{document=**} { allow read, write: if true; }
match /users/{id} { allow read, write; }            // no condition = allowed
// ✅
match /users/{uid} {
  allow read: if request.auth != null && request.auth.uid == uid;
  allow write: if request.auth != null && request.auth.uid == uid;
}
```
- `match /{document=**}` with a permissive rule overrides everything else (rules are additive: a single allow is enough).

## FB2. Expired or dated "test mode" rules — High (A01)
```js
// ❌ generated by the console
allow read, write: if request.time < timestamp.date(2026, 12, 31);
```
Public until the date. Replace with rules based on `request.auth`.

## FB3. `request.auth != null` alone — High (A01)
"Logged in" ≠ "owner". With open registration (email/anonymous), it is almost public.
```js
// ❌
match /orders/{id} { allow read, write: if request.auth != null; }
// ✅
match /orders/{id} {
  allow read: if request.auth != null && resource.data.userId == request.auth.uid;
  allow create: if request.auth != null && request.resource.data.userId == request.auth.uid;
  allow update: if request.auth != null && resource.data.userId == request.auth.uid
                && request.resource.data.userId == resource.data.userId;
}
```
- With **anonymous** auth enabled, `request.auth != null` is true for any visitor.

## FB4. Modifiable privilege fields — Critical (A01)
A user who can write their own `users/{uid}` document can give themselves `role: "admin"`, `credits`, `premium`.
```js
// ✅
allow update: if request.auth.uid == uid
  && !request.resource.data.diff(resource.data).affectedKeys().hasAny(['role', 'credits', 'premium']);
allow create: if request.auth.uid == uid
  && request.resource.data.keys().hasOnly(['name', 'avatar', 'createdAt']);
```
- Roles: prefer **custom claims** (`request.auth.token.admin == true`), set only through the Admin SDK.

## FB5. Missing data validation — Medium (A04)
No type/size check (`request.resource.data.text is string && request.resource.data.text.size() < 2000`) → storage of large documents, arbitrary content.

## FB6. Open Realtime Database — Critical (A01)
```json
// ❌ database.rules.json
{ "rules": { ".read": true, ".write": true } }
// ✅
{ "rules": { "users": { "$uid": {
  ".read": "auth != null && auth.uid === $uid",
  ".write": "auth != null && auth.uid === $uid" } } } }
```
- `".read": "auth != null"` at the root = the whole database readable by any registered user (High).

## FB7. Storage rules — High (A01)
```js
// ❌ storage.rules
match /{allPaths=**} { allow read, write: if request.auth != null; }
// ✅
match /users/{uid}/{file} {
  allow read: if request.auth.uid == uid;
  allow write: if request.auth.uid == uid
    && request.resource.size < 5 * 1024 * 1024
    && request.resource.contentType.matches('image/.*');
}
```

## FB8. Cloud Functions without checks — High to Critical (A01)
- `onRequest` is a public HTTP endpoint: verify the token (`admin.auth().verifyIdToken(req.headers.authorization)`).
- `onCall`: check `request.auth` (v2) / `context.auth` (v1) **and** ownership of the received IDs.
- The Admin SDK **bypasses all rules**: each function must do its own authorization.
```ts
// ❌
export const deleteOrder = onCall(async (req) => { await db.doc(`orders/${req.data.id}`).delete(); });
// ✅
export const deleteOrder = onCall(async (req) => {
  if (!req.auth) throw new HttpsError("unauthenticated", "Login required");
  const ref = db.doc(`orders/${req.data.id}`);
  const snap = await ref.get();
  if (snap.get("userId") !== req.auth.uid) throw new HttpsError("permission-denied", "Forbidden");
  await ref.delete();
});
```
- CORS `cors: true` / `origin: "*"` on functions that read a session cookie: Medium.

## FB9. Committed service account — Critical (A02)
JSON file containing `"type": "service_account"` and `"private_key"` → full admin access to the project. Remove it, **revoke the key** in IAM, use the environment's default credentials.

## FB10. App Check and quotas — Low (A04)
Without App Check, any script can call Firestore/Functions with the public config: this makes abuse easier (costs, spam). Report as Low; if costly functions (AI, SMS, email) are exposed → Medium.

## FB11. Auth — Medium (A07)
Email/password sign-up without email verification used as proof of identity (`request.auth.token.email_verified` not checked in rules that rely on email); allowed domains too broad.
